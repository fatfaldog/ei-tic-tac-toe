# Design

## Context

`applySettingsOk()` в `ui.js` применяет черновик (`game.applySettings`) и закрывает окно — новая партия не начинается. Двигок применяет `level`/`first` только при следующем `newGame()`. Решение пользователя: OK при изменённых геймплейных настройках (level/first) сразу начинает новую партию; раскладка — не геймплейная, немедленна и перезапуска не триггерит.

## Goals / Non-Goals

**Goals:**
- Немедленное действие геймплейных настроек по галочке.
- Чистая семантика «что изменилось — то и применилось»: раскладка — на месте, геймплей — новой партией.

**Non-Goals:**
- Изменение крестика/Esc (отмена без применения).
- Автоперезапуск при цикле прямо в диалоге (до галочки) — нет, только по подтверждению.

## Decisions

### D1. Сравнение черновика с действующими настройками в `applySettingsOk`
Перед применением сравниваются `settingsDraft.level`/`first` с `game.settings`: любое различие → после `applySettings` вызвать `newGame()`. Только `digitLayout` изменился → без перезапуска (раскладка действует немедленно через `applySettings`). Ничего не изменилось → без перезапуска.

### D2. Оркестрация в UI, не в Game
`Game` остаётся чистым («настройки применяются к новой партии»); решение «перезапустить сейчас» — политика UI, живёт в `applySettingsOk`. Движок и ИИ не трогаются.

### D3. Тесты
Смоук: (а) изменить уровень+первый ход → OK → поле очищено, при «Комп» компьютер сходил (крестик при новом правиле); (б) изменить только раскладку → OK → поле НЕ очищено (пара ходов сохранена), клавиша 7 работает по-новому; (в) отмена — без изменений, как раньше.

## Risks / Trade-offs

- [Перезапуск сносит текущую партию без предупреждения] — осознанное поведение из запроса; черновик виден в диалоге, отмена доступна крестиком.

## Migration Plan

Правка одного метода + тесты; откат — git revert. Pages обновится автоматически.
