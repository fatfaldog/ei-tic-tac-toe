# Design

## Context

Знаки захардкожены: `engine.js` `sideMark()` возвращает `'X'` для игрока всегда, победа маппится `win.side === 'X' ? playerWon`; `ai.js` вшиты `'O'`/`'X'` в `easyMove` (завершение/блок) и в минимакс (максимизирует `'O'`); призрак фокуса — текстура крестика. `renderCell` в `ui.js` уже знаковый (классы `cross`/`nought` по знаку), UI почти готов. Решение пользователя (автора игры): канон — классика, первый ходящий играет крестиками; прежнее допущение фиксированных знаков (архив `port-krestiki-to-web`, D6) и оговорка «смена знака вне рамок» (`add-keyboard-gamepad-input`) опровергнуты.

## Goals / Non-Goals

**Goals:**
- Знаки по праву первого хода: первый — крестики; расклад меняется от настройки.
- ИИ и движок не зависят от того, каким знаком играет компьютер.
- Призрак отражает текущий знак игрока.
- Оба расклада покрыты тестами (включая «Тяжелый» крестиками — непроигрышность).

**Non-Goals:**
- Выбор знака отдельной настройкой (только вывод из права первого хода).
- Изменение уровней ИИ, текстов исходов, окон, навигации.

## Decisions

### D1. Знаки назначает движок в `reset()` по `whoFirst`
`Engine.reset()`: `this.marks = { first: 'X', second: 'O' }`; сторона, ходящая первой (`current` при старте = `whoFirst`), получает `'X'`. Публичные аксессоры `playerMark`/`computerMark` вычисляются из `whoFirst` (`whoFirst === 'player' ? X : O` для игрока). `sideMark(side)` остаётся, но читает назначение. Победа: `status = (win.side === this.playerMark) ? 'playerWon' : 'computerWon'`.

### D2. ИИ принимает знаки параметрами
`ai.js`: `easyMove(board, myMark, oppMark)` — `completingCell(board, myMark)` / `completingCell(board, oppMark)`; минимакс параметризуется `me`/`opp` (максимизация `myMark`). `AI.pickMove(level, board, marks)` — оркестратор `Game.computerTurn()` передаёт `{my, opp}` из движка. Обёртки `hardMoves(board, myMark)` для тестов. Логика уровней не меняется — только отвязка от конкретных символов.

### D3. Призрак — два варианта текстуры
CSS: `.cell.focused.ghost::after` (крестик, как сейчас) + `.cell.focused.ghost-nought::after` (текстура нолика `cell-a-1.jpg`, та же полупрозрачность ~0.45 и поправка центрирования из D-порта). `ui.js`: `focusView` возвращает `'ghost'`/`'ghost-nought'` по `engine.playerMark`.

### D4. Тесты: параметризация + оба расклада
- `engine-tests`: сценарии знаков переписываются через `engine.playerMark`/`computerMark`; добавляются кейсы «Комп» первым → компьютер X, игрок O (фиксация знаков, победа ноликами игрока).
- `ai-tests`: полный перебор непроигрышности «Тяжелого» гоняется в обоих назначениях знаков; «Легкий» — completing/block с `myMark='X'`.
- `ui_smoke`: блок «Комп первым» ожидает крестик от компьютера и нолик от игрока; призрак-нолик проверяется при «Комп».

## Risks / Trade-offs

- [Регресс фиксированных тестов] —大面积 X/O-ассерты обновляются; риск пропуска минимизируется полным прогоном трёх наборов.
- [Призрак-нолик на текстуре с подложкой] — используем исходный JPEG (подложка чёрная, клетка прозрачная — на тёмном поле читается, проверено портом ноликов).
- [Память о старом допущении в архивах] — не правим архивы; опровержение зафиксировано в proposal.
