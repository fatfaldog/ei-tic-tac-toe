# Proposal

## Why

Репозиторий синхронизирован с GitHub (`fatfaldog/ei-tic-tac-toe`, публичный), но игра доступна только локально: чтобы поиграть, нужно клонировать репозиторий. GitHub Pages позволяет отдавать готовый статический сайт из `web/` по постоянному URL без сервера и сборки — игра становится доступной по ссылке.

## What Changes

- Новый GitHub Actions-воркфлоу `.github/workflows/deploy-pages.yml`: при push в `main` (и вручную) публикует содержимое `web/` на GitHub Pages через artifact-деплой (`actions/upload-pages-artifact` + `actions/deploy-pages`); тестовые страницы `web/tests/` в публикацию не входят.
- Файл-маркер `web/.nojekyll` — страховка от Jekyll-обработки публикации.
- `README.md` в корне репозитория (сейчас его нет): описание проекта, локальный запуск и **пошаговая инструкция включения GitHub Pages** (Settings → Pages → Source: GitHub Actions — единственный ручной шаг, его выполняет пользователь), URL игры, порядок обновления сайта.
- Код игры, ассеты и инструменты не меняются; каталог `old_compiled/`, `openspec/`, `tools/` в публикацию не попадают.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `game-ui`: добавляется требование «Доступность через GitHub Pages» — автоматическая публикация сайта из `web/` при push в `main`, без тестовых страниц, с функциональностью, идентичной локальной версии.

## Impact

- Новые файлы: `.github/workflows/deploy-pages.yml`, `web/.nojekyll`, `README.md`. Существующие файлы не изменяются.
- Внешний шаг (вне репозитория, делает пользователь один раз): включение GitHub Pages с источником «GitHub Actions»; без него воркфлоу завершится ошибкой с понятным сообщением — инструкция в README.
- Результат: сайт по адресу `https://fatfaldog.github.io/ei-tic-tac-toe/` (все ссылки в игре относительные — субпуть поддерживается; кастомный домен не нужен).
- Требование спеки «Автономная работа» (file://) сохраняется без изменений: Pages — дополнительный способ запуска, не замена.
