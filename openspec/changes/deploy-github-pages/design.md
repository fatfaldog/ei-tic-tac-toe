# Design

## Context

Репозиторий `fatfaldog/ei-tic-tac-toe` синхронизирован с GitHub (публичный, ветка `main`, чистое дерево). Игра — готовый статический сайт в `web/` (36 файлов, ~1.4 МБ) с полностью относительными ссылками; тестовые страницы лежат в `web/tests/`. Вариант публикации выбран в explore-режиме: **A — Actions-воркфлоу с artifact-деплоем** (альтернативы «перенос в корень» и `docs/` отклонены: первый тянет в публикацию exe/openspec/tools, второй требует переименования каталога; orphan-ветка `gh-pages` избыточна для статики). Решения пользователя: тесты не публиковать, Pages включает сам (инструкцию — в README), кастомный домен не нужен.

## Goals / Non-Goals

**Goals:**
- Сайт игры по постоянному URL, обновление пушем в `main` без ручных шагов.
- В публикации только `web/` минус `tests/`.
- README, по которому автор сам включит Pages и обновляет сайт.

**Non-Goals:**
- Кастомный домен, HTTPS-настройки, кэш-инвалидация (всё делает GitHub).
- Публикация тестов, исходников, `old_compiled/`.
- Изменения кода игры.

## Decisions

### D1. Artifact-деплой вместо ветки
`actions/configure-pages` → сборка `site/` → `actions/upload-pages-artifact` → `actions/deploy-pages`. Не требует веток/копий: репозиторий остаётся единственным источником, публикация — производная от `web/`. Требуемые permissions: `pages: write`, `id-token: write`, `contents: read`; триггеры — `push` в `main` (пути `web/**` + сам воркфлоу) и `workflow_dispatch`.

### D2. Исключение тестов — копия без `tests/`
`upload-pages-artifact` публикует каталог целиком, без фильтров. Поэтому шаг `rsync -a web/ site/ --exclude tests` (ubuntu-latest содержит rsync) и публикация `site/`. Побочный плюс: публикация изолирована от будущих файлов в `web/`, которые тоже не захотим наружу.

### D3. `web/.nojekyll`
При artifact-деплое Jekyll не применяется, но маркер стоит копейки и страхует от смены способа публикации (например, на branch-based).

### D4. Ручной шаг вынесен в README
Воркфлоу заработает только после Settings → Pages → Source: **GitHub Actions**. Это единственное действие вне репозитория; до него деплой-джоба будет падать с диагностикой GitHub — в README описаны и включение, и первая проверка (открыть URL, убедиться в 404 на `/tests/…`).

### D5. Триггер по путям
`on.push.paths: [web/**, .github/workflows/deploy-pages.yml]` — правки `openspec/`/`tools/` не пересобирают сайт лишний раз; `workflow_dispatch` оставляет ручной запуск для отладки.

## Risks / Trade-offs

- [Pages не включён → первый прогон падает] → README с пошаговым включением; повторный запуск воркфлоу после включения.
- [Jekyll-обработка] → `.nojekyll` (D3).
- [Относительные пути при субпуте `/ei-tic-tac-toe/`] → проверено в explore-режиме: абсолютных ссылок нет, всё работает из субпути.

## Migration Plan

Только добавление файлов; откат — удалить три файла. Порядок: закоммитить и запушить → включить Pages (README) → проверить URL; повторный push/`workflow_dispatch` при необходимости.
