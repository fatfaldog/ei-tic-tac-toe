# Proposal

## Why

Все изображения подключены через CSS-фоны, поэтому браузер грузит их лениво: текстуры знаков — в момент первого хода, курсор ПЗ — при первом наведении, плиты и существа диалогов — при первом открытии окон (второе существо настроек — при первом цикле уровня). Визуально это поп-ин на ровном месте. Попутно в публикации лежит мёртвый `plate-new-game.png` (195 КБ) — после правки приёмки его заменила стандартная галочка.

## What Changes

- Двухфазный прогрев кэша изображений в `ui.js`: фаза 1 сразу при старте — ассеты первоначального состояния (текстуры знаков `cell-a/b.jpg`, курсор `ei-arrow.png`, плиты галочки/крестика результата); фаза 2 после `window load` + `requestIdleCallback` — всё для окон (заголовки плит, существа настроек, фон и плита «Об авторе», плита «Результат»).
- Прогрев — `new Image().src` для списка (греет HTTP-кэш; когда CSS запросит фон — он уже локален). Без вёрсточных хаков.
- `web/assets/img/plate-new-game.png` удаляется из публикации; исходник (`references/new_game.png`) и генератор (`tools/make_new_game_plate.py`) остаются — файл восстанавливается одной командой.

### Modified Capabilities

- `game-ui` — новое требование «Предзагрузка ресурсов»: ассеты первоначального состояния доступны до первого взаимодействия, ассеты окон прогреваются фоном; окна открываются без видимой подгрузки.

## Impact

- Код: `web/js/ui.js` (списки фаз + прогрев, вызовы из `UI.init`), удаление файла `web/assets/img/plate-new-game.png`.
- Тесты: смоук — прогрев не падает в стабе (списки экспортируются для проверки полноты), мёртвый ассет отсутствует.
- Совместимость: поведение без сети не меняется (прогрев локальных файлов); `file://` работает; размер публикации −195 КБ.
