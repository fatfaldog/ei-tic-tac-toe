# Design

## Context

См. proposal.md — Why (подсказка раскладки на поле, перегруппировка настроек).

Сейчас: настройки — три статические строки в `web/index.html` (`set-row-level/first/layout`), в `ui.js` им соответствуют массивы `SETTING_KEYS`/`SETTING_ROW_IDS`/`SETTING_LABELS` и позиция `settingsPos` (0–2 строки, 3 — OK, 4 — X). Движок хранит `{level, first, digitLayout}` и валидирует их в `applySettings` (`web/js/engine.js`). Клетки — абсолютные `button.cell`, знаки — классы `cross`/`nought`, призрак — `::after` у `.focused`; `::before` свободен. Раскладка клавиш живёт в `DIGIT_MAPS` (`web/js/input.js`, значения `reading`/`numpad`).

## Goals / Non-Goals

**Goals:**
- Номер клетки = клавиша, выбирающая её при текущем порядке нумерации; рендер без перестройки DOM, обновление немедленно.
- Минимальное вторжение в существующую модель строк настроек и клавиатурную навигацию по ним.

**Non-Goals:**
- Сохранение настроек между сессиями (localStorage) — вне скоупа.
- Превью номеров на поле, пока окно настроек открыто (поле за модальным окном; применяется по OK).
- Переименование внутренних значений движка `reading`/`numpad` — меняются только пользовательские метки.

## Decisions

1. **Рендер номеров — `::before` + `data-digit`, без дочерних узлов.** На `button.cell` ставится атрибут `data-digit`, CSS рисует цифру: `.board.digits-on .cell::before { content: attr(data-digit); … }`. Альтернатива — `<span>` в каждой клетке: потребовала бы перестройки детей и аккуратности с делегированием кликов (`closest('.cell')` не затронуто, но шумнее). Атрибут обновляется точечно, цифра живёт в CSS.
2. **Вид и место.** Нижний левый угол клетки (выбор пользователя из диалога), мелкий кегль (~10–11px), светло-коричневый тон палитры ПЗ (~#c8a874, финальный оттенок — по приёмке на реальном фоне), лёгкая тень для читаемости на чёрных клетках и текстурах; `pointer-events: none` — цифра не влияет на мышь. Призрак знака остаётся по центру (`::after`), конфликтов нет.
3. **Пересчёт номеров.** Одна функция `renderDigits()` в `ui.js`: по `game.settings.showDigits` вешает/снимает класс `digits-on` на `#board`, по `game.settings.digitLayout` проставляет `data-digit` каждой клетке (обратный индекс `DIGIT_MAPS`: клетка → клавиша). Вызывается из `buildBoard()` и после `applySettings`. Альтернатива — хранить цифру при создании клеток — отвергнута: смена порядка нумерации требовала бы пересборки.
4. **Модель настроек.** В `engine.settings` добавляется `showDigits: true` (boolean), `applySettings` валидирует тип. Геймплейным ключом остаётся пара `level`/`first` — `showDigits` и `digitLayout` действуют немедленно, партию не перезапускают (существующая логика `applySettingsOk` не меняется).
5. **Строки и группы в окне.** `SETTING_KEYS = ['level','first','showDigits','digitLayout']`, в HTML — две группы с неинтерактивными заголовками `div.settings-group-title` («Геймплей» и «Управление с клавиатуры»), подложка заголовков чуть темнее строк. Заголовки без `tabindex` — сами выпадают из Tab-порядка и из `SETTING_ROW_IDS`, так что `settingsPos` (теперь 0–3 строки, 4 — OK, 5 — X) и логика стрелок не меняются структурно. Метки: `showDigits: {true:'Да', false:'Нет'}`, `digitLayout: {reading:'Нативный', numpad:'Нумпад'}`.
6. **Внутренние значения не переименовываются.** Ключ `reading` остаётся `reading` — трогает `DIGIT_MAPS`, движок и логические тесты без изменения поведения; пользователь видит только «Нативный»/«Нумпад».

## Risks / Trade-offs

- Цифра поверх текстуры занятой клетки: риск пестроты — закрывается кеглем/прозрачностью и приёмкой на реальных текстурах; отключается настройкой.
- `settingsPos` перестаёт совпадать с DOM-порядком строк (заголовок между ними): следить, чтобы `renderSettings` подсвечивал по `SETTING_ROW_IDS`, а не по детям рамки.
- Смоук завязан на «Раскладка 1-9»/«Читающая»/`set-row-layout` — потребуется синхронное обновление проверок (новые имена, новая строка, группа, номера).
