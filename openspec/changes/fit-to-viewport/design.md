# Design

## Context

См. proposal.md — Why. Разметка: `body > .scene` (min-height:100vh, flex-center) содержит И окно игры, И оба модальных `modal-wrap` (`position: fixed; inset: 0`). Игра фиксированных пикселей: окно 417+2 по ширине, ~442 по высоте; для расчёта берём габариты сцены с запасом: 421 × 446. В `<head>` нет viewport-меты. Модалки — единственные fixed-элементы; blessing: transform на предке делает fixed потомков позиционируемыми от него же (CSS spec), значит они масштабируются вместе со сценой бесплатно.

## Goals / Non-Goals

**Goals:**
- Вписывать игру в любую область: телефон (портрет/ландшафт), мелкий iframe.
- На больших экранах — строго 1:1, ноль визуальных отличий.

**Non-Goals:**
- Адаптивная вёрстка (ре-лейаут под мобильный) — игра остаётся фиксированным пиксель-дизайном, только масштаб.
- Управление жестами (свайпы фокуса и пр.) — тач-тапы уже работают через клик-модель; отдельная тема.
- Fullscreen API, блокировка зума браузера (`user-scalable` не трогаем).

## Decisions

1. **Viewport-мета обязательна и первична.** Без неё мобильный браузер рендерит ~980px и сам уменьшает — любой скейлер поверх этого врёт. `<meta name="viewport" content="width=device-width, initial-scale=1">`.
2. **JS-скейлер, не CSS-only.** Кандидат `scale: min(calc(100vw/421px), …)` требует деления длин в calc (спецификация math Level 4, неровная поддержка). JS тривиален, надёжен и тестируется в смоуке. Формула: `fitScale() = Math.min(w/играW, h/играH, 1)`, округление до 4 знаков против дрожания transform. Размеры игры берутся замером из DOM (`game-window` offsetWidth/offsetHeight; резервные константы 421x446 — только для тест-стаба) — правка приёмки: угаданные константы не совпали с реальностью на Samsung S25 Ultra. Первый расчёт — в requestAnimationFrame после layout; пересчёт на `resize`, `load`, `orientationchange` (+100мс) и `visualViewport.resize`. Страница не скроллится (`html,body { overflow: hidden }`): скейлер всегда вписывает игру, а макетное переполнение не может создать скролл/срез. При `?debug` в URL — крошечный HUD с числами (viewport, размер игры, масштаб) для диагностики на живых устройствах.
3. **Что масштабируем: `.scene`.** Он уже содержит окно и модалки; `transform: scale(s)` + `transform-origin: center center`. Layout-бокс сцены не меняется (transform не влияет на поток), flex-центрирование сохраняется. Fixed-модалки привязываются к transform-предку и ездят вместе — подложка накрывает сцену (на мобильном сцена ≈ вьюпорт, разницы с текущим поведением нет).
4. **Пересчёт**: при `UI.init()` и на `resize` (пассивный слушатель). iOS-URL-bar меняет innerHeight — resize это покрывает. `ResizeObserver` не нужен: слушаем окно, для iframe его innerWidth/innerHeight и есть область.
5. **Экспорт `UI.fitScale(w, h)`** (чистая функция от размеров) для смоука: проверяются типовые раскладки без эмуляции окон.

## Risks / Trade-offs

- Нецелый `scale` чуть размывает текст (картинкам безразлично; тексты мелкие, заметность низкая). Альтернатива — ступенчатый масштаб — визуально хуже (то влезает, то нет).
- `min-height: 100vh` на iOS со страницей-«резинкой» — скейлер считает по фактическому innerHeight на момент события, рассинхрона не возникает.
- Скроллбары у десктопа при узком окне: innerWidth уже учитывает их — формула честна.
