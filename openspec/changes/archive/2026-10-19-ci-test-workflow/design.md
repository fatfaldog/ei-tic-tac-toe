# Design

## Context

См. proposal.md — Why. Существующий `.github/workflows/deploy-pages.yml` задаёт домотный стиль: кириллические комментарии, path-фильтры на `push`, `concurrency` с `cancel-in-progress`, actions v4/v5. Тесты — чистый Node без зависимостей (`run_tests.js`, `ui_smoke.js` на DOM-стабе): `npm install` не нужен. Флейк «Игры за нолики» исправлен ранее (60 стабильных прогонов) — иначе CI краснел бы случайно.

## Goals / Non-Goals

**Goals:**
- Тесты гоняются автоматически на каждый релевантный пуш; живой статус — бейджем в README.
- Минимальная нагрузка на очередь GitHub Actions (она сегодня деградировала).

**Non-Goals:**
- Шлюзование деплоя тестами (`needs`/`workflow_run`) — цепочка удвоит ожидание в очереди; отдельное будущее решение.
- Матрица версий Node, lint, coverage — один Node 22, проект без зависимостей.
- Изменение самих тестов.

## Decisions

1. **Отдельный workflow, не job в деплой-воркфлоу.** Бейджу нужен собственный файл; триггеры у тестов шире (`tools/**`), чем у деплоя (`web/**`).
2. **Триггеры**: `push` в `main` с path-фильтрами `web/**`, `tools/**`, `.github/workflows/tests.yml` (правки `openspec/`, `references/` тесты не меняют — не занимаем очередь); `pull_request` в `main` с теми же фильтрами (сегодня пушим напрямую, но PR стоимостью ноль).
3. **`concurrency: tests-${{ github.ref }}` + `cancel-in-progress`** — устаревшие пуши отменяются, паттерн деплой-воркфлоу.
4. **Node 22 через `setup-node@v4`**, без кэша (кэшировать нечего). Шаги: checkout → setup-node → `run_tests.js` (три файла) → `ui_smoke.js`. Ожидаемо ~20 секунд.
5. **README**: бейдж `[![Tests](…/actions/workflows/tests.yml/badge.svg)](…/actions/workflows/tests.yml)` в начале абзаца про тесты; числа «43 проверки логики / N проверок интерфейса» удаляются, команды остаются с пояснением, что актуальное число печатается при запуске (живой статус — в бейдже).
6. **Верификация** первого рана — по бейджу/странице Actions: API GitHub сегодня под rate-limit, а ран может ждать очередь. Зелёный бейдж на README — критерий готовности.

## Risks / Trade-offs

- Очередь GitHub: первый ран может стартовать не сразу — ожидаемо, `cancel-in-progress` держит нагрузку минимальной.
- Бейдж показывает последний ран на `main`; в PR-ветках статус виден на странице PR (checks).
