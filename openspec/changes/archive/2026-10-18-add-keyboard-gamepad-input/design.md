# Design

## Context

Сейчас весь ввод — мышиный: в `web/js/ui.js` (222 строки) десять обработчиков `click`/`change`, ни одного `keydown`, Gamepad API не используется. Слои чистые: `engine.js` (правила), `ai.js` (ходы ИИ), `ui.js` (DOM). Решения explore-режима: полный охват (поле + меню + настройки + оверлеи + «Об авторе»), читающая раскладка 1-9 по умолчанию с переключением на нумпадовую в настройках, единая модель фокуса (мышь и клавиатура/геймпад двигают один фокус), призрак — всегда крестик игрока (смена знака по первому ходу — вне рамок), настройки не сохраняются между сессиями.

## Goals / Non-Goals

**Goals:**
- Ввод с клавиатуры и геймпада, покрывающий все экраны игры.
- Единый фокус, общий для мыши и клавиатуры/геймпада: смешанное управление (навигация мышью, подтверждение Enter) работает.
- Наглядная индикация фокуса: свечение, призрак крестика на пустой, красная подсветка занятой.
- Тестируемость: маппинги, раскладки, edge-детекция и рендер-состояние фокуса — чистые функции.

**Non-Goals:**
- Смена знака игрока по праву первого хода; сохранение настроек; экран переназначения клавиш; тач-жесты; вибрация геймпада.

## Decisions

### D1. Слой ввода = действия, а не устройства
`web/js/input.js` сводит всё к семи действиям `UP/DOWN/LEFT/RIGHT/CONFIRM/BACK/MENU` и колбэку-диспетчеру. Устройства:
- клавиатура: `keydown` на `document` → `keyAction(event)` (стрелки/WASD/Enter/Space/Esc/F10/M; 1–9 — отдельным колбэком прямого выбора клетки);
- геймпад: опрос `navigator.getGamepads()` → `gamepadEdges(prev, cur)` → те же действия.
Порядок скриптов: `engine → ai → ui → input → main`; `ui.js` в `init()` создаёт диспетчер и вызывает `Input.attach(dispatch)`, `input.js` вешает слушатели. `input.js` не знает про DOM игры — только события.

### D2. Focus-машина в ui.js: контексты
Состояние: `context` (`board | menu | settings | about | result | farewell`) + `focus.cell` (0–8|null) + `focus.control` (пункт меню/чекбокс). Правила: первый клавиатурный/геймпадный ввод в контексте `board` ставит фокус в центр; `mouseover` на клетке двигает `focus.cell`; уход мыши фокус сохраняет; клик = фокус + подтверждение (текущее поведение); открытие меню/окна переключает контекст, клеточный фокус замораживается (подсветка бледнеет через класс на `.game-area`). Меню: стрелки по пунктам, Enter — активация. Настройки: 4 чекбокса в сетке 2×2, стрелки ходят по сетке, Space/A — переключение пары, Esc/B — закрыть.

### D3. Рендер фокуса — чистая функция + CSS-классы
`focusView(cellIdx, board, currentSide, status)` → `'ghost' | 'glow' | 'invalid' | 'dim'` (пустая+очередь игрока → ghost; пустая+очередь компьютера → glow; занятая → invalid; игра на паузе контекста → dim). CSS: `.cell.focused` — тёплое свечение (`box-shadow` золотистым); `.cell.focused.ghost::after` — `cell-b-1.jpg` с `opacity: .45` (фон текстуры чёрный, пустая клетка тоже — призрак читается без «протечек»); `.cell.focused.invalid` — красная рамка/свечение. Обновление — в общем рендере клеток, без отдельного цикла.

### D4. Gamepad: rAF-опрос только при подключённом паде
`gamepadconnected` запускает `requestAnimationFrame`-цикл, `gamepaddisconnected` останавливает. Маппинг standard: `buttons[12..15]` D-pad, `axes[0..1]` стик с мёртвой зоной 0.5, `buttons[0]` A=CONFIRM, `buttons[1]` B=BACK, `buttons[9]` Start=MENU. `gamepadEdges(prevState, curState)` возвращает действия только на переходе «отпущено→нажато» — удержание не повторяется. Функция чистая, тестируется в node подачей последовательностей состояний.

### D5. Раскладка 1–9 — третья группа настроек
Значение `settings.digitLayout: 'reading' | 'numpad'` рядом с `level`/`first` в оркестраторе `Game` (метод `applySettings` расширяется). Маппинги-константы: `reading: 1..9 → 0..8`; `numpad: 7,8,9,4,5,6,1,2,3 → 0..8`. Третья группа в окне настроек в стиле существующих (`.pz-label` + пара `.pz-check`), низ формы (~y=256/280, координаты уточняются визуально по фону); переключение немедленное.

### D6. preventDefault и конфликт клавиш
Стрелки/Space/Esc/F10 в момент, когда действие потреблено игрой — `preventDefault()` (прокрутка, меню браузера). Ввод текста нигде не редактируется — конфликтов нет. Активные модификаторы (Ctrl/Cmd) игнорируем, чтобы не перехватывать системные сочетания.

## Risks / Trade-offs

- [F10 открывает меню браузера] → `preventDefault` при получении keydown; если браузер перехватывает раньше — есть дубль M.
- [Геймпад не подключён/не поддерживается] → цикл опроса не запускается, игра полностью работает без пада; отсутствие API (`navigator.getGamepads`) проверяется.
- [Призрак на JPEG-текстуре с чёрным фоном] → фон совпадает с пустой клеткой, полупрозрачность даёт эффект «призрака», проверяется визуально.
- [Смешение hover-фокуса и модальных окон] → контекстная машина изолирует ввод; мышь вне поля не мешает модали.

## Migration Plan

Только добавление `input.js` и точечные правки `ui.js`/`index.html`/`style.css`; существующее поведение мыши не меняется (регресс проверяется прогоном всех текущих тестов). Откат — удалить файл/правки.

## Open Questions

- Точная позиция третьей группы настроек на фоне пергамента — подгоняется визуально в задаче (низ формы ожидаемо свободен).
