# Design

## Context

Источник — `old_compiled/Krestiki.exe` (PE32, Delphi, ~1 МБ) плюс `borlndmm.dll` и `cc3260mt.dll`. Исходников нет; запустить оригинал нечем (Windows-бинарник, wine на машине нет). В ходе разведки exe полностью распарсен (чистым Python stdlib), содержимое задокументировано:

| Ресурс | Содержимое |
|---|---|
| RCDATA `TFORM1` | Главная форма «Крестики-нолики», клиентская область 417×418. Фон `Image1` 418×423 (JPEG). Девять клеток `Image2..Image10` 97×97 (JPEG 93×112, одинаковые) и девять `Image11..Image19` 97×97 (JPEG 96×94, одинаковые). Девять чёрных `TPanel` (clBtnText) под клетками. Меню: «Игра» → «Новая игра», «Настройки», «Выход»; пункт «Об авторе» |
| RCDATA `TSETTINGSW` | Форма «Настройки» 341×319. Два фоновых JPEG 348×321. Подписи «Уровень сложности:» (clYellow), «Кто ходит первым?» (clAqua); чекбоксы «Легкий» (clSkyBlue), «Тяжелый» (clRed), «Я» (clSkyBlue), «Комп» (clRed) |
| RCDATA `TABOUTAVTOR` | Форма «Об авторе» 344×384. Фоновый JPEG 350×366, read-only Memo с текстом про fatfaldog/yurasim, «Проект: Перепись ПЗшников» (ei-census.eclub.lv), благодарности PPyatachok и ksaont |
| CURSOR 1..7 | 7 кастомных курсоров по 308 байт |
| ICON `MAINICON` | Иконка приложения |

Все строки DFM — в UTF-8, русские. Извлечение ассетов проверено: скрипт на stdlib разбирает PE → `.rsrc` → RCDATA → бинарный DFM (TPF0) → компоненты + JPEG (payload `[len][класс][4b size][данные]`).

Пользовательские решения: гибридная графика (оригинальные JPEG + web-детали), «Легкий» = выигрыш → блок → случайно, чистый статик без сборки.

## Goals / Non-Goals

**Goals:**
- Точная передача визуала оригинала за счёт прямого переиспользования извлечённых ресурсов и геометрии форм (координаты из DFM).
- Полностью автономная страница, работающая по `file://` двойным кликом.
- Воспроизводимый пайплайн извлечения ассетов (скрипт остаётся в репозитории).

**Non-Goals:**
- Полная responsive/мобильная адаптация: окно фиксированной пропорции, при необходимости пропорциональное масштабирование контейнера.
- Звук, мультиплеер, онлайн-таблицы — в оригинале отсутствуют.
- Перерисовка/апскейл оригинальной графики (используем как есть, с её JPEG-артефактами).
- Сохранение настроек между сессиями (в оригинале не было; при каждом запуске — «Легкий» + «Я»).

## Decisions

### D1. Расположение: папка `web/` в корне репозитория
```
web/
  index.html
  css/style.css
  js/engine.js  js/ai.js  js/ui.js  js/main.js
  assets/img/*.jpg  assets/cursors/*.cur  assets/icon.ico
  assets/layout.json
tools/extract_assets.py
```
Корень остаётся чистым, `old_compiled/` и `openspec/` не смешиваются с игрой. Альтернатива — файлы в корне — отклонена: захламляет корень и мешает будущим изменениям.

### D2. Извлечение ассетов — скрипт на чистом Python stdlib (`tools/extract_assets.py`)
Основа — проверенный в разведке код: парсер PE-заголовков и `.rsrc`, чтение RCDATA-форм, парсер бинарного DFM (TPF0: свойства, vaSet/vaList/vaBinary, префиксы 0xF0+), вырезка JPEG из `Picture.Data`. Скрипт пишет в `web/assets/`:
- 22 JPEG с говорящими именами (`main-bg.jpg`, `cell-a-1..9.jpg`, `cell-b-1..9.jpg`, `settings-bg-1/2.jpg`, `about-bg.jpg`; 1+9+9+2+1=22 — в инвентаре изначально значилось 23, но один сигнатурный offset находился в `.text` вне ресурсов и оказался ложным срабатыванием сканера);
- `layout.json` — дерево компонентов трёх форм (класс, имя, Left/Top/Width/Height, Caption, Color) и текст Memo — источник геометрии и текстов для UI;
- 7 курсоров `.cur` и иконку.
Альтернативы (icoutils/7-zip/Resource Hacker) дают меньше: DFM всё равно парсить своим кодом, а они не везде есть. Скрипт идемпотентен, exe открывает только на чтение.

### D3. Классические скрипты вместо ES-модулей
ES-модули не работают по `file://` (CORS в Chrome). Поэтому отдельные файлы `engine.js` → `ai.js` → `ui.js` → `main.js`, подключённые несколькими тегами `<script src>` в порядке зависимостей; взаимодействие через один глобальный объект-неймспейс (`window.Krestiki`). Это сохраняет и `file://`, и разумную modularность без сборки.

### D4. Слои архитектуры JS
- `engine.js` — чистые правила: состояние поля 3×3, ходы, детект победы/ничьей, события через простой колбэк-интерфейс. Не знает про DOM.
- `ai.js` — выбор хода: `easyMove(board)` (1. завершить свою линию из двух; 2. заблокировать линию из двух крестиков; 3. случайная пустая) и `hardMove(board)` — минимакс с мемоизацией по позиции (состояний ≤3⁹), при равных оценках — случайный выбор среди лучших.
- `ui.js`/`main.js` — DOM: окно, поле из 9 кнопок, меню, модальные окна «Настройки» и «Об авторе», сообщение результата, применение настроек.
Разделение повторяет границы capabilities (`tic-tac-toe-game`, `computer-opponent`, `game-ui`) — каждую часть можно менять и тестировать изолированно.

### D5. Отрисовка окна и поля — по геометрии DFM
Контейнер 417×418 (клиентская область формы), фон — `main-bg.jpg` (418×423, слегка обрежется — как в оригинале). Клетки — абсолютно позиционированные кнопки 97×97 с координатами из `layout.json` (колонки Left ≈ 45/168/278, строки Top ≈ 32–36/152/272). Изображения клеток растягиваются до 97×97 (VCL Stretch) — делаем так же. Чёрные панели под клетками воспроизводим как тёмный фон/рамки клеток.

### D6. Состояния клеток и карта ассетов
Исправленная модель (по итогам просмотра и замечания пользователя; исходная гипотеза «A=пустая плита, B=метка, вторая метка дорисовывалась кодом» оказалась неверной):
- **пустая клетка — чёрная TPanel оригинала** (`Color=clBtnText`, `BevelOuter=bvNone`, `OnClick=Panel1Click`): по модели VCL оконная TPanel всегда рисуется над графическими TImage, поэтому изначально видны плоские чёрные квадраты-«кнопки», а изображения меток скрыты под ними; при ходе панель в оригинале скрывалась, открывая метку;
- **набор B (96×94, симметричные диагональные лучи) — крестик игрока**;
- **набор A (93×112, яркое кольцо) — нолик компьютера** (уточнено по внешнему виду: отрисовывается как «нолик»);
- рисование недостающей метки кодом (CSS/SVG) не требуется — обе метки существуют как оригинальные ассеты.

### D7. Окна «Настройки» и «Об авторе» — модальные слои на одной странице
Отдельные браузерные окна/маршруты не нужны: это оверлеи 341×319 и 344×384 на оригинальных фонах, с точными текстами из `layout.json`. Чекбоксы-«радиокнопки» (в оригинале TCheckBox с взаимоисключающей логикой) реализуем как стилизованные под оригинал переключатели с логикой radio. Настройки применяются к следующей партии («Новая игра»), текущая партия не прерывается.

### D8. Сообщение результата — стилизованный оверлей
Поведения оригинала при победе/ничьей не знаем (не запустить). Решение: оверлей в стилистике с текстами «Вы победили!», «Компьютер победил», «Ничья» и кнопкой «Новая игра». Зафиксировано как осознанное допущение; при желании тонкая настройка текстов не меняет архитектуру.

### D9. Курсор — стрелка из самой игры «Проклятые Земли»
Основной (и единственный) курсор web-версии — стрелка из ПЗ, вырезанная из скриншота пользователя: `tools/ei_cursor_extract.py` сегментирует яркое ядро с контуром (заливка по порогу + 3 кольца диляции), уменьшает box-фильтром в 2 раза (с премультипликацией альфы) и пишет RGBA-PNG `assets/cursors/ei-arrow.png` (20×19, hot-spot — остриё (3,0)); по запросу пользователя размер уменьшен вдвое от исходного кропа. Скриншотов конкретно нашей фан-игры в сети нет: сайт «Переписи ПЗшников» мёртв, в Wayback Machine остался только каркас (раздел «Файлы» без этой игры). PNG вместо `.cur` обязателен: Safari не поддерживает `.cur` в CSS `cursor` (поэтому пользователю показывались fallback'и — «стрелочка»/«кисть»). Семь монохромных курсоров из exe в поставку не входят: по viewing-расшифровке пользователя это дубликаты дефолтных курсоров ранних Windows (кисть, песочные часы, ресайзы, «действие невозможно») — в web-версии не нужны; их инвентаризация с расшифровкой хранится в `layout.json` (`shipped: false`).

### D10. Пункт меню «Выход»
`window.close()` (сработает только для вкладок, открытых скриптом), при неудаче — «прощальный экран»: затемнение и статичная картинка вместо активного поля. Требование спецификации покрыто обоими исходами.

## Risks / Trade-offs

- [Назначение двух наборов клеточных JPEG неизвестно] → задача классификации картинок в начале реализации; итог: пустая клетка — чёрная TPanel, набор B — крестик, набор A — нолик (исправлено после первого просмотра, см. D6).
- [Поведение оригинала местами недоступно для сверки (сообщения о результате, «Выход»)] → допущения зафиксированы (D8, D10) и легко правятся текстом, не архитектурой; финальную приёмку делает пользователь, знакомый с оригиналом.
- [`file://`-ограничения браузеров] → классические скрипты (D3), никаких `fetch()`/модулей; все данные — `<img>`, CSS и inline-JSON.
- [Фиксированный растровый размер 417×418 на больших/Retina-экранах] → при необходимости пропорциональное масштабирование контейнера (`transform: scale()`), не входящее в базовый объём.
- [JPEG-артефакты оригинала останутся] → сознательный trade-off ради аутентичности (выбор пользователя — гибрид с приоритетом оригинала).

## Migration Plan

Новые файлы только добавляются (`web/`, `tools/`); существующие каталоги не трогаются. Откат — удалить `web/` и `tools/`. Развёртывание: скопировать/открыть `web/index.html`; сервер не нужен.

## Open Questions

- Какая именно метка (крестик/нолик) на наборе B и как визуально оформлена вторая метка — решается просмотром ассетов в начале реализации (D6), на спеки и задачи не влияет.
- Нужен ли блокирующий «ход компьютера» с видимой задержкой (пауза перед ответом ИИ) или мгновенный ответ — косметика таймингов, решается при реализации UI.
