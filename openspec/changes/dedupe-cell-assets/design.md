# Design

## Context

Установлено побайтовым сравнением (shasum): 9 JPEG набора A (нолики, по 11 289 байт) и 9 JPEG набора B (крестики, по 9 677 байт) — по одному уникальному изображению на набор. В коде используются только `cell-a-1.jpg`/`cell-b-1.jpg`. Дубликаты — артефакт порта: в DFM 2006 года каждая клетка имела собственный TImage с той же картинкой.

## Goals / Non-Goals

**Goals:**
- Один файл на набор меток в поставке; инвентарь DFM в layout.json сохранён.
- Нулевое визуальное изменение (рендер байтово тот же).

**Non-Goals:**
- Оптимизация плиток/фонов (plate-settings.png 104 KB и пр.) — отдельная тема.
- Переименование остальных ассетов.

## Decisions

### D1. Имена `cell-a.jpg` / `cell-b.jpg`, генерация — по первому компоненту набора
Экстрактор при встрече `Image2` (первый компонент набора A) пишет `cell-a.jpg`; для `Image3..Image10` — ничего (дубликаты пропускаются с записью в layout.json количества склеенных компонентов). Аналогично для набора B. `cellStateMap` ссылается на новые имена.

### D2. Очистка старых файлов — вручную при переходе
Экстрактор не удаляет неизвестные файлы (безопасность: не трогает плиты/курсоры, созданные другими инструментами). Удаление 18 устаревших `cell-a-*`/`cell-b-*` — отдельный шаг `git rm` в задачах; после него повторный прогон экстрактора идемпотентен.

### D3. CSS — 4 замены имён
`.cell.cross`, `.cell.nought`, `.cell.focused.ghost::after`, `.cell.focused.ghost-nought::after`. Позиции/размеры не меняются.

## Risks / Trade-offs

- [Забытая ссылка на старое имя] — проверка: grep `cell-[ab]-[0-9]` по web/ пуст после правок; битых ссылок 0.
- [Проверка экстрактора жёстко ждала 22] — заменяется на 8 (2 метки + 6 прочих JPEG).

## Migration Plan

Правки экстрактора → перегенерация → `git rm` дублей → CSS → тесты/смоук → пуш (Pages обновится автоматически). Откат — git revert.
